# Mira audit and repair — 2026-09-30

This review uses the 2026-09-29 audit of `21322d65a6858f86982f97691ca0e15883326062`
as a checklist, then examines the implementation, including its existing local
repairs. Existing edits were preserved and independently checked. This report
records local validation before publication; it does not by itself establish
cross-platform release certification. Evidence paths under `build/` refer to
local artifacts and are not included in the source repository.

## Additional findings from repair review

- A synchronous child could cause its join continuation to destroy TaskScope
  before Runner::start returned. ASan reproduced the use-after-free. Active
  frames now remain owned by the starting stack until its resume unwinds.
- TaskScope now reserves the join frame before accepting children; cleanup does
  not need another allocation after a producer failure. Retirement, event-loop
  cancellation callbacks and shutdown no longer allocate in noexcept paths.
- HTTP client begin/send_body/finish/read_body exceptions could leave an active
  connection whose destructor aborted. Guard-based invalidation covers all
  operations, not just duplex exchange.
- HTTP request parsing also rejects empty Content-Length list items and control
  characters in chunk extensions. Keep-alive classification performs no dynamic
  allocation inside its noexcept function.
- MQTT reconnect now includes already-buffered Client events before changing
  session state; lifecycle/discard notices cannot silently bypass the budget.
  Client AUTH Success is rejected because only the server may send that reason.
- A duplicated H2 install-consumer case attempted to create an existing test
  directory; the duplicate was removed. A TLS-disabled DoH example unused-global
  error exposed by newer Clang was corrected.
- H3 fuzzing uses separate connections for bidirectional request bytes and
  unidirectional control/QPACK bytes; rejection of one path cannot mask the other.
- CI previously left protocol dependency internals uninstrumented and allowed
  recoverable UBSan findings during fuzzing. Separate instrumented prefixes now
  use the consumer's compiler, and the sanitizer/fuzz jobs halt on UBSan errors.
- Pinned OpenSSL and the independent curl verification client were behind
  security updates. Their verified source pins are now 3.5.9 and 8.22.0;
  dependency-specific verification is separated below from earlier full runs.

## Dependency security review

Official announcements were checked live on September 30. The original CI's
OpenSSL 3.5.1 pin missed subsequent security fixes. The current LTS patch is
3.5.9, released September 29; its official archive was downloaded and verified
against SHA-256
`603f5602e2eef00d77fbd429d34dcd5822bb301757a1bc9cdb24c670f1eb859a`.
All three CI source-build steps now use that version and hash.
Sources: [OpenSSL downloads](https://www.openssl-library.org/source/) and
[3.5.9 release](https://github.com/openssl/openssl/releases/tag/openssl-3.5.9).

[CVE-2026-35189](https://openssl-library.org/news/vulnerabilities/#CVE-2026-35189)
is relevant to ordinary peer certificate processing, even without CRL checks
enabled. Production packages should contain the corresponding fixes: OpenSSL
3.5.9, 3.6.5, or a vendor package with those fixes backported. Mira's API minimum
is not a claim about distribution patch status. The full matrices above used
the existing OpenSSL 3.6.4 installation; separate patched-dependency verification
is recorded in the validation table rather than relabeling those earlier runs.
The isolated 3.5.9 build passed all 28 selected native TLS/QUIC/H3 tests without
falling back to system OpenSSL. Many other
new OpenSSL QUIC advisories concern its built-in QUIC implementation; Mira uses
ngtcp2, so those advisories are not automatically Mira findings.

nghttp2 1.70.0 is newer than the fixed version for
[CVE-2026-27135](https://github.com/nghttp2/nghttp2/security/advisories/GHSA-6933-cjhr-5qg6).
ngtcp2 1.22.1 is the fixed version for
[CVE-2026-40170](https://github.com/ngtcp2/ngtcp2/security/advisories/GHSA-f523-465f-8c8f).
The [nghttp3 security page](https://github.com/ngtcp2/nghttp3/security/advisories)
had no public advisories; that does not establish absence of vulnerabilities.

The original curl 8.16.0 is an independent test executable, not Mira's runtime
dependency. Its known issues were reviewed against the actual loopback CLI
options; no applicable exploit path was confirmed. The maintained verification
builder now pins [curl 8.22.0](https://github.com/curl/curl/releases/tag/curl-8_22_0).
The downloaded archive matched the official release asset SHA-256
`f7ef3ae8a22e521f289803fe93543eb64c329b58aa73a9e224dfd915a2a5f4f7`.
An independent build with HTTP2/HTTP3 enabled passed all three interop checks in
the validation table. This client used system OpenSSL 3.6.4; it is separate from
the native Mira test build using OpenSSL 3.5.9.

The next pass re-examined failure interleavings and boundary conditions instead
of treating the first pass's green tests as proof of completeness. The following
are additional findings, separate from the original 50-item checklist.

corrected paired probe uses identical Release libraries and differs only in

## Remaining validation boundaries

- Native Windows, Linux and mobile runtime tests were not executed in this local
  macOS review. Windows cross-compilation is not native IOCP/ASan execution.
- macOS LeakSanitizer was not run. ASan and UBSan cover the checks described above.
- No new full Autobahn campaign, multi-host/WAN benchmark or long-duration soak
  is implied. CI requires strict Autobahn results and runs the added regressions;
  its result for these local changes still needs a future CI run.
- Budgets are explicit protocol/queue bounds, not a hard process-RSS cap.
  Deadline enforcement for user callbacks is cooperative.
